# Prṛthak 0.6 - implementation and evidence boundary

31 October 2026. This is a lab development release. The 20-server pilot has not started, and no production or physical multi-site HA certification is claimed. The main demonstration inventory retains 14 synthetic servers. Illustrated UI captures are actual staged/demo screens, not connected customer hosts, live tenant approval or infrastructure health.

## Prerequisite distinction

The static Go endpoint/stock POSIX installer has no Python dependency. Empty source-bank preparation uses Python 3.6+ stdlib and firewalld. Standalone signature verification has Python 3.8+ syntax and the release cryptography>=44 dependency floor; use approved Python 3.10+ administration tooling before extraction. Current cryptography 50.0.2 requires Python>=3.9. RHEL 8 default3.6 is not a verifier environment. Controller/signing tools use their own requirements; native RHEL 8/9 acceptance remains external.

## What changed

- Risky managed/imported access changes use an exact requester submission and a different live enabled same-tenant Entra approver. Manual learned grants/source edits/removal and the initial fresh auto-allow scope use the same separation. Database recovery requires **both individuals to be Super Admins**. Shared-token/demo flows are explicitly single-actor lab authority.
- Agent 0.6 verifies pinned Ed25519 assignment envelopes independently of HTTPS/mTLS. Envelopes bind exact endpoint/deployment, version, sources/services, approval/protection, learning and polling intent. The optional offline provider has reviewed artifacts and public trust only, with no online seed fallback. Dedicated release signatures can authenticate exact Linux archives before extraction; unsigned local outputs remain labelled lab packages.
- Prepared dual IPv4/IPv6 source banks support larger managed and additive learned source sets while retaining the small 64-rule adapter. Bank setup is a separate maintenance operation; policy application never reloads firewalld. Observation uses ephemeral runtime-only log rules with a firewalld timeout, not permanent collector rules.
- Business metadata stays dashboard-owned. Manual overrides precede exact-IP CSV, then longest-prefix subnet location and unassigned. /24 wins over /16 over /8. Exact normalized CIDRs are unique; an IP cannot classify endpoints into different DCs, and ambiguous multi-owner CSV matches are withheld. Authenticated agent bodies alone supply live inventory IPs; peer/forwarded/NAT/planned addresses never replace them.
- Endpoint mTLS renewal/overlap, registry revocation and one-time recovery credentials, controller HTTPS import/generation/restart/rollback, and dedicated internal-service leaf renewal/suspension are implemented. `ca_cert` is web HTTPS trust; optional `endpoint_ca_cert` pins a different endpoint issuer. Ed25519 assignment trust is separate from both. Response material cannot silently replace existing pins.
- Super Admin Services now reviews the current node’s application port (1–65535), requires the exact phrase/dependency acknowledgement and reports durable verified handover or old-port restoration. The configured application/SSO origin and external LB/agent/peer/DNS/firewall settings are preserved; demo is review-only.
- Super Admin notification settings review exact Slack/HTTPS-webhook/TLS-SMTP destinations and recipients. Encrypted shared configuration, durable per-occurrence outbox/retry, provider acknowledgements, explicit duplicate-aware retry and masked secrets are implemented. Notifications default off. A test message requires its own destination confirmation.
- Supervised GUI database recovery uses a verified local archive, matching current PKI/Vault/safety ledger and two live Entra Super Admins. It drains/fences writers, verifies candidates/readiness, retains originals/protected rollback material and invalidates sessions/unused credentials/pending approvals/automatic learning. Queueing or a disconnected dashboard is not successful recovery. Missing live trusted context blocks online recovery; no keys or safety history are invented.

## Local release-signing provenance

A separate **local project** release authority was generated for the 0.6 archives. Its signature proves only that local authority and exact bytes; it is not an organization-approved authority or evidence of independent public-key distribution. Before DC use, adopt/pin its public fingerprint through the organization's approved independent process and verify every archive before extraction. An adjacent downloaded public manifest is not automatically trusted.

The original illustrated-guide baseline passed **528 controller tests** (all five PostgreSQL acceptance flags, 79.744s), **150 integration checks** (PostgreSQL/CLI/fixed-manager flags, 91.528s) and **201 dashboard tests**. Go regular (17.237s), race (22.419s), vet and make check passed at that checkpoint. The integration suite includes simulated fixed-manager contract/failure checks as well as actual wire/process fixtures; the separate real Compose/public-router smoke has the scope stated above.

The later 31 October security-remediation freeze passed **653 controller tests** (all five private PostgreSQL flags, 88.249s), **183 integration cases** (182 passed, one Mac/Linux-kernel skip; 112.227s), **230 dashboard tests**, Go race (23.680s), vet and make check. Separate actual Linux checks cover kernel peer credentials and four process-fence regressions. All twelve confirmed application findings have scoped code fixes, including whole-assignment replay protection, retained rollback mutation leases, bounded exact policy/review reads and atomic versioned edits. Final source-only images exclude controller tests/build tooling and passed entrypoint/corporate-TLS smoke. The top-right account dropdown replaces the sidebar user card and adds profile/display preferences and appropriate sign-out. See the [completed code assessment and remaining VA findings](security-assessment-2026-10-31.md). The upstream/container findings remain open; these checks are not deployment approval or VA signoff.

## Required before the real pilot

Validate genuine licensed RHEL 8/9 firewalld/systemd/SELinux/polkit and the intended Ubuntu kernel/systemd builds. Verify real management/bastion paths and out-of-band recovery, dual-stack/reload/reboot behavior, native database-host watchdog reset/fencing, physical WAN partitions/site loss, redundant ingress and measured RPO/RTO. Complete actual tenant Entra/MFA, both independent reviewers and revoked-identity acceptance, intended notification-provider delivery, separately protected off-node backups and an owned recovery drill. Run the actual pilot workload and measure resource/headroom/incident behavior before expanding.

Complete compromised-controller/CA decommission requires fenced offline CA and all-secret recovery. Suspending a member does not revoke copied database credentials or an internal issuing CA. Formal authoritative IP ownership, egress/container-network enforcement, automated canary/cohort upgrade orchestration and signed RPM/DEB repositories are not supplied by the implemented host-ingress adapter.
