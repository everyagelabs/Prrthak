# Current user requirements and delivery map

This Markdown is the current operational companion to the historical 38-requirement PDF. It records requested behavior and how the implementation addresses it. The historical PDF, dated assessments and illustrated imagery are not relabeled as current evidence.

## Current authority and roles

An authorized Entra Admin's ordinary policy/server/group/tag Save or Apply publishes changed intent directly for ordinary per-port hosts. On an existing whole-server default-deny host, a changed deny-bearing bundle stays pending until an Admin completes a fresh dedicated review and manually ticks its downtime acknowledgement. There is no second-person requirement, approval-mode selector, 20-host approval boundary or seven-day approval-mode expiry. Read Only cannot mutate; Super Admin additionally owns users and privileged platform settings. Endpoint local opt-ins are never silently enabled by a policy save.

Deny/restrictive imported-rule changes, restrictive learned edits/removal and destructive database recovery retain their explicit same-actor confirmation steps. Recovery remains Super Admin-only. Exact preview/scope/revision/nonces, current authority, protected management health, journaling, rollback and actual endpoint outcomes remain in effect. Queued intent is never labelled kernel-applied.

## Later explicit user directions

| Direction | Current behavior and evidence boundary |
|---|---|
| Direct Admin change → effect | Normal saves publish affected ordinary per-port intent directly. Changed whole-server default-deny bundles wait for the dedicated exact review and downtime tick; this is the same Admin, not a checker workflow. Changes/history records delivery and outcomes. Endpoint protections still gate actual application. |
| Explicit whole-server inbound default deny | Starts disabled and never activates through an ordinary policy save. A reviewed push covers the frozen selected endpoints, new inbound connections, IPv4/IPv6 REJECT fallback and named control exceptions. Established sessions remain. Disable preserves the last applied grants; a matching removal receipt precedes normal compilation. |
| Optional continuous per-port hits | Disabled by default; exact frozen target/port scopes run until stopped through short signed leases, with rolling 1–24-hour maximum retention, last-hour view and CSV. New scopes select conntrack accepted connections, verified NFLOG denied packets or both, with separate units and coverage gaps; historical journal records keep their legacy contract. This creates no access policy. |
| Faster small-pilot discovery | A separately selected polling preset applies 30s control / 60s discovery to at most 20 explicit endpoints. This is a timing preset, not an approval mode; normal fleet discovery remains 900s unless changed by the operator. |
| Restart and nonresponding agents | Every agent process begins with fresh OS/firewall/service inventory using its existing enrolled identity. Independent health evaluation raises a critical agent-offline alert after max(180 seconds, three control intervals), then records recovery. Fast listener checks preserve the separately configured full-inventory fallback. |
| Optional dependency preparation; preserve UFW | Unchecked schema-3 GUI options authorize bounded native package installation with journaled startup suppression and/or private UFW export. No UFW cutover, firewalld activation or automatic enforcement occurs. [Details](endpoint-discovery-and-preparation.md). |
| Risky ports with reasons and regulatory references | [Risk & compliance](risky-ports-regulatory.md) supplies a configurable advisory catalogue, listener findings and source-backed CERT-In/RBI mapping. Findings do not automatically block traffic, and the mapping does not certify compliance or complete organizational controls. |

## Supporting components and remaining evidence

The Go service, Python controller, browser dashboard, signed assignments, mTLS, durable metadata/traffic storage, fixed local manager and supervisors support these requirements; they are implementation components rather than additional original requirements. See [architecture](architecture.md), [API](api-contract.md), [agent](../agent/README.md) and [current GUI installation](pilot-gui-installation.md).

Code and isolated acceptance evidence do not establish native RHEL/Ubuntu behavior, physical DC/WAN/quorum/fencing, live organization Entra/MFA, provider delivery or production readiness. Those deployment gates remain explicit. Supported exact firewalld subsets do not imply universal vendor/direct/NAT policy management; unsupported contexts remain view-only. No new aggregate test totals are asserted here.
