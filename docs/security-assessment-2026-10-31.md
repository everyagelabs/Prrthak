# Prṛthak · पृथक् — application security assessment and VA

Assessment date: **31 October 2026**. Scope: this standalone unpublished 0.6 project, its controller/dashboard, Go endpoint, installers, privileged helper and configured appliance images. This report is the post-baseline security addendum to the deployment guide.

**Subsequent capacity work:** the [new controller capacity/installer checkpoint](controller-capacity-5000.md) supersedes this audit's failed one-worker timing result. It includes bounded worker-local connections, fresh pool-admission/fencing checks and two additional SQLite report-race regressions. Its actual policy edit reaches all 5,000 identities in 30.684 seconds under the documented profile. The source hashes, test totals, image IDs and package hashes below describe the earlier audit freeze; new artifacts have their own provenance and do not retroactively change that record. The upstream/vendor VA findings and deferred native/DC gates remain open.

**Status: the twelve confirmed application findings have code remediations and passing scoped regression evidence.** The final source and validation images are frozen. This completes the requested code-remediation pass; it does not close the remaining upstream/container findings. **VA clearance and production/pilot approval have not been granted.** The user is handling DC deployment and has deferred native test machines.

No real DC server, production database, organizational Entra tenant, customer notification destination or 20-server pilot was used. Tests ran against disposable local files, loopback services, fresh PostgreSQL databases and isolated containers. The running preview's existing inventory is retained. No code, private key or database was uploaded to an external scanner.

## Final review bounds and dashboard changes

Managed and learned review construction now checks the actual compact ASCII-escaped storage encoding incrementally, before appending additional target/binding matrices. The complete review, enclosing initial-learning session and later confirmation metadata are checked before persistence or approval insertion. Oversized authority is refused explicitly; operators must review a smaller cohort. Source lists, frozen membership and approved ports are never silently shortened. Failure tests verify that review, approval, history and audit records remain unchanged, including when confirmation metadata alone exceeds the budget. This closes the identified construction/write bypasses as well as public read amplification; it does not make every internal inventory/compile path constant-cost.

The health evaluator raises a deduplicated critical `firewall_service_unavailable` alert when a fresh authenticated discovery report says firewalld is not running. Recovery requires a later fresh running report. Missing heartbeat or unknown state cannot establish recovery, and a stopped daemon does not establish whether its kernel rules remain. Detection follows the configured discovery interval; this is not an immediate independent host probe or an automatic daemon restart.

The duplicate bottom-left user card is removed. The top-right account dropdown shows the actual identity and role, read-only profile, browser-local compact-table/reduced-motion preferences, Super Admin-only user management and login-mode-appropriate sign-out. The demo truthfully has no authenticated session to sign out; local-token disconnect does not revoke the shared token. Preferences store only the two display booleans and never change roles or identity. Keyboard navigation, escaping, storage failure, role boundaries, cookie/CSRF logout and unsaved page-draft preservation have regression coverage.

The running synthetic preview was checked in the browser: profile and preferences opened correctly without saving a preference, combined `application=billing` plus `port=8443` returned exactly one matching policy, and clearing those filters restored all 14 endpoints. The final tab shows Overview with the account menu open. [Account-menu screenshot](../output/screenshots/security-audit/account-menu.jpg), [combined-filter screenshot](../output/screenshots/security-audit/combined-policy-filters.jpg). This browser check used demo mode; Entra logout and other role states were covered by isolated tests, not a live tenant.

## Dynamic and source validation

The real Gunicorn/TLS fixture exercised **112 distinct passing controls**. It used an isolated random loopback origin, synthetic Entra identities and signed test JWTs, actual application authentication/authorization, and at most two simultaneous connections. Coverage included the four access levels over 15 route families, user administration, private backups/downloads, CSRF/cross-Origin rejection, forwarded-certificate/header spoofing, traversal, issuer/audience/nonce/signature/algorithm/time errors, state replay, disabled-user session reuse and malformed/oversized HTTP framing. A still-configured valid legacy Super bearer returned 401 with Entra enabled.

The original slow GET remained open and served another request after 36.489 seconds. After the fix, it closed at 30.252 seconds; HEAD/OPTIONS/TRACE body cases also closed. Partial TLS and headers closed at approximately 20 seconds, and an incomplete POST closed at approximately 30 seconds. A fixture-only handler delay returned 201 after 32.028 seconds once its POST body had been fully consumed. A timeout can occasionally emit a generic HTTP500 before closure; this protocol-quality limitation is recorded, not represented as renewed indefinite worker occupancy. Results: [DAST manifest](../.local/security-audit/controller-dast-final.json).

Frontend review inspected the routed templates, drawers, review dialogs, downloads and browser credential handling. Offline structural checks rendered 349 HTML fragments, 54 containing adversarial text/attribute payloads, without detecting an injected active tag, event attribute or executable URL. These are source/fake-DOM structural checks, not a complete HTML5/SVG browser penetration test. No confirmed DOM XSS or credential-exfiltration issue was found in that scope.

Bandit and manual SQL review distinguish heuristics from confirmed vulnerabilities. The initial fixture-inclusive scan had 267 findings; the first production-only scope had 102 heuristic findings, including 44 SQL-expression warnings and no High-severity scanner findings. Fixed table/column identifiers, validated schema identifiers and parameterized values must be assessed through their callers. The final production-only scan covers 60 Python files / 17,973 lines and has **161 heuristic warnings: 120 Medium, 41 Low, zero High**, including 103 B608 SQL-expression warnings, with zero scan errors. The historical 44 SQL warnings retain their caller ledger; the later bounded-view construction has a final manual review of code-owned tables/paths/aliases and bound request values. These are scanner observations, not 161 confirmed vulnerabilities. [Exact final scan summary](../.local/security-audit/bandit-production-final-summary.json), [manual SQL disposition](../.local/security-audit/sql-bandit-triage.md).

- Initial controller/database images contained old pip/setuptools and an unused inherited `gosu` binary. Images are rebuilt with available OS upgrades and patched install tooling; unnecessary packaging tooling and inherited `gosu` are removed from the runtime images after dependency installation. ## Regression, performance and artifacts

The frozen code passed **653 controller tests** with all five private PostgreSQL acceptance flags (88.249s), **230 dashboard tests**, and **183 integration cases** (112.227s): 182 passed and one Linux-kernel-only case skipped on Mac. That kernel peer/DAC path was separately verified in an actual isolated Linux container. The controller aggregate includes actual PostgreSQL approval/session/policy/managed navigation and concurrency cases. `make check` also passes. Logs: [controller](../.local/security-audit/controller-final.log), [integration](../.local/security-audit/integration-final.log), [dashboard](../.local/security-audit/dashboard-final.log).

Full Go race tests (23.680s) and vet pass. The Darwin suite has 140 top-level tests, including explicitly gated native skips. Four actual Linux process-fence regressions and actual Linux peer-credential/account-reservation checks pass. Native RHEL/systemd/firewalld acceptance is a separate requirement.

The **final frozen-source** private workload completed two cycles for 5,000 distinct virtual mTLS identities in **123.853 and 84.086 seconds**. All 5,000 cycles succeeded in each phase with zero HTTP failures/retries, 2,741 conditional 304 replies overall, all 10,000 synthetic flow events retained and no pending flow batches. **Both phases missed the 60-second target. This configuration has no 5,000-endpoint capacity clearance.** The prior checkpoint's 57.772/26.709-second result is preserved separately; timing alone does not establish a source-change regression cause.

The matched workload used one Gunicorn worker, 32 threads, 64 concurrent virtual clients, two monitor-policy services and 20 sources/service on one private PostgreSQL instance. The warm phase also included 100 discovery reports and 100 learning endpoints sending 100 events each. Certificates were seeded before measured phases. The fixture hash is unchanged from the earlier checkpoint; final launch controller hashes match the frozen host source and exact final image. Fresh owned benchmark databases were removed afterward. This is not 5,000 Linux processes, an enrollment storm, native collection/enforcement, a long soak, synchronous WAN replication or site failover. [Exact workload, source hashes and results](../.local/security-audit/mtls-fleet-5000.json), [previous checkpoint](../.local/security-audit/mtls-fleet-5000-before-f02.json), [runbook and limitations](mtls-scale-validation.md).

Linux amd64/arm64 agent packages are rebuilt and signed with the existing **local project** release authority. Both final bundles passed exact source-doc/binary comparisons, archive safety checks, separately held public-pin signature verification and same-length tampering rejection after the documentation freeze. [Release verification](../.local/security-audit/release-verification.json). This authority is not an independently approved organization release authority; the approved distribution/pin process remains a deployment prerequisite.

## Remaining deployment gates and hardening scope

1. Resolve or formally accept the remaining exact-image vendor advisories, with affected paths and compensating controls reviewed by the deployment security owner. A clean top-level Python or agent Go scan does not clear the OS/container/etcd findings. Source/base tags are still mutable; recording exact audit image IDs is not an installer-wide immutable-image policy.
   The final single-worker 5,000-identity workload also missed its 60-second target in both phases. Profile and qualify the intended worker/database/load-balancer configuration and operational workload before claiming that polling cadence at fleet scale. No polling default was silently relaxed to make the test pass.
2. Complete native disposable RHEL 8, RHEL 9 and intended Ubuntu 26.04 kernel/systemd/firewalld/SELinux/polkit checks, including daemon timing, forced termination, reboot/reload, rollback failure, IPv6 and genuine bastion/SSH paths. These machines were explicitly deferred by the user; no access request is repeated here.
3. **Do not enable endpoint enforcement or automatic learning on controller, database-voter or load-balancer infrastructure during this pilot.** A public LB URL cannot establish all local backend/published ingress ports. Native topology-specific protection acceptance must precede that use.
4. Complete actual Entra/MFA and revoked-identity tests, real LB/SNAT/client-certificate behavior, native database watchdog/fencing, site/WAN partitions, measured RPO/RTO, provider delivery and off-node recovery drills.
5. Keep one agent per protected state directory. Custom private paths, terminal journal retention/quotas, and arbitrary helper OOM/SIGKILL combinations need additional hardening/endurance work; no exploit was claimed without a demonstrated lower-trust writer or native failure proof.
6. Controller compromise remains a high-impact trust event. Joined controllers share intended authority. An independently protected offline signer adds separation; an online signing key readable by a compromised controller does not. A revoked stop cannot be learned during complete control-path withholding before the endpoint has received it; signature expiry bounds stale authority.
7. Authorization on already-admitted ordinary requests is not represented as a universal transaction barrier against concurrent user revocation. Critical user/approval/witness paths have stronger current-state checks; the source-review hypothesis is not promoted to a confirmed escalation without proof.

The audit is a finite source/dynamic/dependency assessment, not an independent production penetration test or security certification. The 20-server pilot and real 5,000-endpoint rollout have not started.
